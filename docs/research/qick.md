## 0. Our firmware, from primary sources

From [fwREADME] and [fwHWH]:

- **tProc v2** `qick_processor` rev 27. Timing clock 614.4 MHz, core 204.8 MHz. Memories: **program 4096 words, data 16384, waveform 1024**. External start pin PMOD1_0.
- **Clock groups:** `[tProc core, tProc timing, DAC tile 0, DAC tile 2]` and `[ADC tile 0, ADC tile 2]`.
- **DAC output power mode:** 20 mA.
- **gen0** = DAC_B (tile 0, blk 0) and **gen1** = DAC_A (tile 2, blk 0). Both are `axis_signal_gen_v6` with fs = 9830.4 Msps, fabric clock 614.4 MHz, a 32-bit DDS with range 9830.4 MHz, and 65536 complex envelope samples (6.667 µs). RFDC interpolation is 1 (`C_DAC0/2_Interpolation=1`).
- **ro0** = ADC_D (tile 0 blk 0) and **ro1** = ADC_C (tile 0 blk 2). Both have an `axis_avg_buffer`.
- **ro2** = ADC_B (tile 2 blk 0) has an `axis_weighted_buffer` with **4096 weights**.
- All three readouts are `axis_dyn_readout_v1`: fs = 4423.68 Msps, decimated to 552.96 MHz, 32-bit DDS. Each buffer holds **16384 accumulated and 16384 decimated** samples (29.63 µs). RFDC decimation is 1.
- **DDR4 buffer:** 2^30 samples (1.94 s), 256 samples per transfer. **MR buffer:** 8192 samples. Both are wired to readouts [0, 1, 2].
- The README was generated by software 0.2.381. The library on the board and on the PC is 0.2.442. 0.2.442 accepts tProc revisions `[21..27]` ([lib] asm_v2.py:2041).

## 1. The tProc v2 programming model (`AveragerProgramV2`)

### 1.1 Structure

You subclass `AveragerProgramV2` and implement `_initialize(cfg)` and `_body(cfg)`. `_cleanup(cfg)` is optional ([lib] asm_v2.py:2681–2821).

The constructor is `AveragerProgramV2(soccfg, reps, final_delay, final_wait=0, initial_delay=1.0, reps_innermost=False, before_reps=None, after_reps=None, cfg=None)`. It **compiles immediately**, and needs only a `QickConfig`, not the board ([lib] asm_v2.py:2726–2738, `self.compile()`).

`make_program()` builds this sequence ([lib] asm_v2.py:2823–2856):

```
set_ext_counter(addr=1)        # shot counter, read by acquire()
_initialize(cfg)
delay_auto(initial_delay)
for each loop (reps first, then add_loop() order): open_loop
    _body(cfg)
    wait_auto(final_wait); delay_auto(final_delay)
    inc_ext_counter(addr=1)
close loops (sweeps are incremented here)
_cleanup(cfg); end()
```

- **Loops.** `add_loop(name, count, exec_before=None, exec_after=None)`: the first loop added is the outermost after "reps" ([lib] asm_v2.py:2764). With `reps_innermost=True`, reps becomes the innermost loop.
- **Averaging axis.** Data is averaged over the reps axis. `avg_level` is 0, or the last level if `reps_innermost` ([lib] asm_v2.py:2757–2762).
- **`_initialize` vs `_body`.** "`_initialize()` runs during compilation (Python side, once); `_body()` runs during execution (tProc side, many times)" ([docs] tutorials/01_Basic_Sequencing.html).

### 1.2 Declarations, pulses and readout configs

A minimal program from [docs] tutorials/01_Basic_Sequencing.html, which is the same pattern as 06 and 07:

```python
class SinglePulseProgram(AveragerProgramV2):
    def _initialize(self, cfg):
        self.declare_gen(ch=cfg['gen_ch'], nqz=1)
        self.declare_readout(ch=cfg['ro_ch'], length=cfg['ro_len'])      # us
        self.add_pulse(ch=cfg['gen_ch'], name="my_pulse", style="const",
                       freq=cfg['freq'], ro_ch=cfg['ro_ch'],              # MHz, freq-matched
                       length=cfg['pulse_len'], phase=cfg['phase'], gain=cfg['gain'])
        self.add_readoutconfig(ch=cfg['ro_ch'], name="my_ro", freq=cfg['freq'], gen_ch=cfg['gen_ch'])
        self.send_readoutconfig(ch=cfg['ro_ch'], name="my_ro", t=0)
    def _body(self, cfg):
        self.pulse(ch=cfg['gen_ch'], name="my_pulse", t=0)
        self.trigger(ros=[cfg['ro_ch']], pins=[0], t=cfg['trig_time'])
```

**`declare_gen(ch, nqz=1, mixer_freq=None, ...)`** ([lib] qick_asm.py:1297)
- `nqz` must be 1 or 2.
- `mixer_freq` is only for generators with `has_mixer`. Passing it to a generator without a mixer only logs a warning.

**`declare_readout(ch, length, ...)`** ([lib] qick_asm.py:1155–1232)
- For **tProc-controlled (dynamic) readouts like ours**, passing `freq`, `phase`, `sel` or `gen_ch` raises `RuntimeError("readout %d is dynamic ... set using tProc instructions")`. Frequency is set with `add_readoutconfig` + `send_readoutconfig`.
- [docs] tutorials/07 shows a `declare_readout(..., freq=...)` example (`PhaseTrackingProgram`). It only works on PYNQ-configured readouts and **fails on ours**.
- `length` is in µs and converted with `us2cycles(ro_ch=...)` at the readout output clock (552.96 MHz for us).
- It warns when `length > 2**16` cycles because the sum buffer could overflow (line 1199). For us that is about 118 µs.

**`add_pulse(ch, name, style=..., freq, phase, gain, length | envelope, ro_ch=None, phrst, stdysel, mode, outsel)`** ([lib] asm_v2.py:2335; params in `StandardGenManager`, asm_v2.py:1701–1716)
- Styles are `const`, `arb` and `flat_top`.
- `mode` is `"oneshot"` or `"periodic"`. `stdysel` is `"zero"` or `"last"` ([lib] asm_v2.py:1598–1647; [docs] topics/gen_config.html).
- Length limits are 3 to 2^16−1 fabric cycles per waveform ([lib] asm_v2.py:1729–1734). At 614.4 MHz that is about **106 µs maximum per const pulse** (computed). For longer CW, use `mode="periodic"` and stop it with the special `"dummypulse"` ([lib] asm_v2.py:1494–1512).
- Envelopes: `add_gauss`, `add_envelope`, `add_cosine`, `add_DRAG`, `add_triangle` ([lib] qick_asm.py:1382–1606). The envelope memory is 65536 samples (6.67 µs) per generator [fwREADME].

**`add_readoutconfig(ch, name, freq, phase=..., phrst=..., outsel=..., gen_ch=None)`** ([lib] asm_v2.py:2389)
- It is stored as a "pulse" for the readout.
- **`send_readoutconfig(ch, name, t)`** pushes it to the readout at time `t` ([lib] asm_v2.py:1514; [docs] firmware/readouts/readout_dynamic.html §5.3).

**Timing calls** ([lib] asm_v2.py:1407–1558):
- `pulse(ch, name, t=0 | "auto")`
- `trigger(ros=[...], pins=[...], t=..., width=None, ddr4=False, mr=False)`
- `delay(t)`: moves the reference time.
- `delay_auto(t=0, gens=True, ros=True)`: reference time becomes the end of the last pulse/readout plus `t`.
- `wait(t)` and `wait_auto(t=0, gens=False, ros=True)`: pause **execution** without moving the reference.
- `resync(t)`

All `t` values are µs relative to the current reference time. They are converted to tProc timing-clock cycles in `TimedMacro.convert_time` ([lib] asm_v2.py:809–841).

v1 → v2 equivalents: `sync_all()` → `delay_auto()`, and `synci(t)` → `delay(t)` ([docs] topics/tprocv2_migration.html).

### 1.3 Units and gain

- Times are in µs, frequencies in MHz, phases in degrees, and gains normalized to −1..1 ([docs] topics/tprocv2_migration.html "Units").
- **Gain to integer.** `to_int(gain, maxv*maxv_scale, trunc=True)` with `maxv = 2**15-2 = 32766` ([lib] drivers/generator.py:13; asm_v2.py:1788–1804). `maxv_scale = 1.0` for v6 ([lib] drivers/generator.py:127). Values are truncated toward zero ([lib] helpers.py:10–40).
- **`flat_top` gain.** The flat segment is played with `gain * 1/2` so that it matches the ramps ([lib] asm_v2.py:1789–1799, 1838).
- **Frequency and phase registers.** Both are 32-bit ([lib] drivers/generator.py:264–270; drivers/readout.py:393–394). Steps are about 2.3 Hz for the generator and about 20.6 Hz for the gen+RO common grid on the RFSoC4x2 ([docs] topics/freq_matching.html).
- **Read back the actual values** after rounding with `prog.get_pulse_param(name, par, as_array=True)` and `prog.get_time_param(tag, par, as_array=True)` ([lib] asm_v2.py:2463, 2517; [docs] tutorials/09 §4.4).

### 1.4 Sweeps

`QickSweep1D(loop, start, end)` is the same as `QickParam(start, {loop: end-start})`. `QickSpan(loop, span)` builds multi-dimensional sweeps by summation ([lib] asm_v2.py:228–254). Example from [docs] tutorials/02_Parameter_Sweeps.html:

```python
self.add_loop("my_sweep", cfg["steps"])
self.add_pulse(ch=gen_ch, name="swept_pulse", style="flat_top", envelope="ramp",
               freq=cfg['freq'], ro_ch=ro_ch, length=cfg['flat_len'],
               phase=QickSweep1D("my_sweep", -360, 720),
               gain=QickSweep1D("my_sweep", 0.0, 1.0))
# 2D: 'gain': 0.4 + QickSpan("loop1", 0.5) + QickSpan("loop2", 0.1)
```

**How sweeps compile**
- The step is `trunc(span/(n-1)/quantize)*quantize`, so the real end point can fall short of the requested one.
- It raises `"requested sweep step is smaller than the available resolution"` if the step rounds to 0 ([lib] asm_v2.py:295–310).
- At `CloseLoop` the swept waveform-memory fields (or registers) are incremented, then restored after the loop ([lib] asm_v2.py:737–796).
- Sweeps **cost no extra waveform-memory entries**. Each distinct pulse or readoutconfig waveform costs one entry (1024 total) [fwREADME]. The size check is in [lib] asm_v2.py:2167–2180.

### 1.5 reps vs rounds

- **`reps`** is the hardware loop. It is the outermost loop by default, so slow drifts average out; `reps_innermost=True` flips this ([lib] asm_v2.py:2714–2718).
- **`rounds`** is an argument of `acquire()`/`acquire_decimated()`. It reruns the whole program from Python and averages in software ("soft averages") ([lib] qick_asm.py:1905–1914, 2009–2010).
- **Shot spacing.** `final_delay` is the gap after the last pulse or readout. `final_wait` (default 0) pauses execution until the readout ends, so the tProc does not run ahead of the buffers ([lib] asm_v2.py:2699–2713).
- **Readout dead time (measured on the bench, 2026-11-04; firmware qick_4x2.bit, ro on ADC_D).** A trigger that arrives less than ~30 ns after the previous window ends is dropped, with no error. The shot counter still counts it, so the streamer reads buffer entries that were never written and returns stale data from earlier runs. With 0 ns gap, 113 of 201 results were fresh at 0.5 µs windows, 135 at 10 µs; 20 ns lost some at 0.5 µs; 30 ns and more lost none. CW Time leaves 50 ns.
- **Data rate to the PC (measured, same day).** Each trigger returns 16 bytes. Over the USB link the PC receives about 8–11 MB/s, so windows shorter than ~2 µs are produced faster than they arrive. The board's timeline is unaffected (the streamer keeps up on the board; no data was lost down to 0.1 µs windows), but a round ends later. Measure timing with long windows, not from round periods at high data rates.

## 2. S21 frequency sweep

### 2.1 In-tProc sweep with a dynamic readout (official pattern)

[docs] tutorials/07_Advanced_Generators_And_Readouts.html §5 ("Full-Speed Generator and Dynamically Configured Readout") describes this as "essential for resonator spectroscopy and electrical delay calibration":

```python
class DynamicFreqSweepProgram(AveragerProgramV2):
    def _initialize(self, cfg):
        ro_ch, gen_ch = cfg['ro_ch'], cfg['gen_ch']
        self.declare_gen(ch=gen_ch, nqz=cfg['nqz'])
        self.declare_readout(ch=ro_ch, length=cfg['ro_len'])
        self.add_readoutconfig(ch=ro_ch, name="myro", freq=cfg['freq'], gen_ch=gen_ch)
        loopbefore = AsmV2()
        loopbefore.send_readoutconfig(ch=cfg['ro_ch'], name="myro", t=0)
        self.add_loop("myloop", self.cfg["steps"], exec_before=loopbefore)
        self.add_gauss(ch=gen_ch, name="ramp", sigma=cfg['ramp_len']/10, length=cfg['ramp_len'], even_length=True)
        self.add_pulse(ch=gen_ch, name="mypulse", ro_ch=ro_ch, style="flat_top", envelope="ramp",
                       freq=cfg['freq'], length=cfg['flat_len'], phase=cfg['phase'], gain=cfg['gain'])
    def _body(self, cfg):
        self.pulse(ch=cfg['gen_ch'], name="mypulse", t=0)
        self.trigger(ros=[cfg['ro_ch']], pins=[0], t=cfg['trig_time'])

config_dyn['freq'] = QickSweep1D("myloop", START_FREQ, END_FREQ); config_dyn['steps'] = 1001
prog = DynamicFreqSweepProgram(soccfg, reps=100, final_delay=1.0, cfg=config_dyn)
freqs = prog.get_pulse_param('myro', 'freq', as_array=True)
iq_list = prog.acquire(soc, rounds=1, progress=True)
iq_complex = iq_list[0][0].dot([1, 1j])
```

- The same `QickParam` is used for both the generator pulse frequency and the readout-config frequency.
- `send_readoutconfig` sits in the loop's `exec_before`, so the new readout frequency is pushed at every step.
- In that notebook's output, 1001 points × 100 reps (100100 shots) took **0.37 s**. This ran on the board, not over Pyro.

**Python loop (the v1 approach).** [gh] qick_demos/06_qubit_demos.ipynb ("Single tone (Resonator) Spectroscopy") and [docs] tutorials/06 §6 rebuild and acquire one program per frequency in a Python loop. The v1 demo notes that RAveragerProgram "cannot be used ... because we need to sweep the frequency of both the DAC and the ADC simultaneously - the tProc can control the DAC frequency, but not the ADC frequency" ([gh] qick_demos/01_Phase_coherent_readout.ipynb, "Summary"). Our dynamic readouts remove that limitation.

**Per-point cost of a Python loop.** Each point means:
- a full compile;
- `config_all()`: stop tProc, load envelopes, set Nyquist, configure readouts, load program ([lib] qick_asm.py:1094–1128);
- per-round buffer configuration, `reload_mem`, `clear_tproc_counter` and start ([lib] qick_asm.py:2265–2298).

Over Pyro each of these is a round trip. Keep a Python loop only for things the tProc cannot sweep, such as external LO steps.

### 2.2 Frequency matching

From [docs] topics/freq_matching.html:

> For coherent measurements, the upconversion frequency (DAC) and downconversion frequency (ADC) must be **exactly equal**. If they are not, the acquired data will show a sliding phase.

> Both sides of the pair must be matched: `add_pulse(..., ro_ch=RO_CH)` and `add_readoutconfig(..., gen_ch=GEN_CH)`.

> `gen_ch` alone is not enough … on the RFSoC4x2 the generator step is 2.3 Hz, the common step 20.6 Hz, and at 100 MHz the difference is 9.2 Hz … each run of the same program returns I/Q at a different angle.

**How the library does it**
- `freq2int(f, thisch, otherch)` quantizes to the LCM of both channels' steps through `calc_fstep_int` ([lib] qick_asm.py:297–415).
- `soccfg.adcfreq(f, gen_ch, ro_ch)` rounds a frequency to the common grid ([lib] qick_asm.py:531–549).
- In a sweep, the `quantize` factor forces the step to a multiple of the common step too ([lib] helpers.py:10–40; asm_v2.py:295–310). Start and step are both on the grid, so generator and readout stay matched at every point.
- The readout register is negated (`FLIP_DOWNCONVERSION`) ([lib] asm_v2.py:1954, 2037–2038).
- **Resolution limit.** The finest sweep step for a matched pair is about 20.6 Hz.

### 2.3 Phase coherence, phase reset and electrical delay

**Coherence model**
- Gen and readout DDSs are "phase-coherent" synthesizers. When frequencies match there is "a constant phase difference φ", and phase vs frequency follows `φ = 2πf·t + φ0` ([gh] qick_demos/01_Phase_coherent_readout.ipynb, intro).
- The dynamic readout's DDS phase accumulates continuously across descriptors. It resets only when a descriptor has `phrst=1` ([docs] firmware/readouts/readout_dynamic.html §3.3–3.4).
- `phrst` is accepted for `axis_signal_gen_v6` pulses and for readout configs ([lib] asm_v2.py:1763–1765; 2405 docstring). Generator semantics: "If 1, it resets the phase coherent accumulator" ([lib] asm_v2.py:1628–1629, 2358–2359).

**What resets DDS start times**
- `QickSoc.pl_reset()`: "The main visible effect of this reset is to reset the start times of all the phase-coherent DDS oscillators" ([lib] qick.py:1314–1318).
- `RFDC.restart_all_tiles()`: "re-lock tile PLLs, reset DDS phases to random values" ([lib] qick.py:346–351).
- In practice, re-check φ0 after any board re-init.

**Electrical delay.** [docs] tutorials/07 §5.1 fits it and removes it:

```python
phases = np.unwrap(np.angle(iq_complex)) / (2*np.pi)
a = np.vstack([freqs, np.ones_like(freqs)]).T
phase_delay = np.linalg.lstsq(a, phases, rcond=None)[0][0]      # us (cycles/MHz)
iq_rotated = iq_complex * np.exp(-1j * freqs * 2*np.pi * phase_delay)
```

The loopback example gave −11.08 ns. The sign follows the library's flipped downconversion; just use the fitted slope.

**Phase wrapping and unwrap**
- Unwrap is only valid if the per-step phase change is below π: `2π·Δf·τ < π`, so `Δf < 1/(2τ)` (derived from the formula above).
- With a cable delay τ of tens of ns this is easy, but a 1001-point sweep over GHz needs enough points.

**What limits the number of sweep points**
- The step must be at least the common frequency step ([lib] asm_v2.py:295–310).
- Program memory and branches: jumps use 11-bit literals, 2048 instructions ([docs] tutorials/09 §2.2). The library handles `pmem_size > 2**11` through `s15` ([lib] asm_v2.py:776–785).
- Time registers are signed 32-bit, about 3.5 s at 614.4 MHz (computed from the formula in [docs] tutorials/09 §2.3).
- In accumulated mode, data is streamed, so point count is **not** limited by the 16384-entry buffer. The tProc must not outrun the streamer, or the streamer raises "Overflowed the averages buffer ... increase relax_delay" ([lib] streamer.py:136–141).
- In decimated mode, `length × trigs × reps × steps ≤ 16384` per channel ([lib] qick_asm.py:2216–2219; [fwREADME]).

## 3. `acquire()` vs `acquire_decimated()`

Both run **on the client**. They are methods of the program object (`AcquireMixin`, [lib] qick_asm.py:1724) and call `soc.*` remotely.

### 3.1 `acquire(soc, rounds=1, load_envelopes=True, start_src="internal", threshold=None, angle=None, progress=True, remove_offset=True, step_rounds=False, extra_args=None)`

([lib] qick_asm.py:1905–1993)

**Return value.** A list with one entry per declared readout (in declaration order). Each entry has shape `(n_reads_per_shot, *loop_dims_without_avg_axis, 2)` with the last axis = (I, Q) ([lib] qick_asm.py:2041–2062). It is averaged over reps (`mean(axis=avg_level)`), then over rounds. For a 1D sweep, `iq_list[ro_idx][0][:, 0]` is I vs frequency ([docs] tutorials/07 §5).

**Scaling**
- `avg /= ro['length']`, then `avg -= iq_offset` ([lib] qick_asm.py:2041–2062).
- The result is the **mean decimated I/Q value per sample in the window**, in ADC units. It does not scale with window length.
- `iq_offset = 0.0` for `axis_dyn_readout_v1` ([lib] drivers/readout.py:451–460).
- Raw integer sums are available from `prog.get_raw()`: shape `(*loop_dims, nreads, 2)`, in time order. Per-round arrays come from `get_rounds()` ([lib] qick_asm.py:1813–1836).

**Data path**
- `finish_round` calls `soc.start_readout(total_count, ...)` and then loops `soc.poll_data()` until all shots have arrived ([lib] qick_asm.py:2337–2357).
- On the board, `DataStreamer` is a thread. It polls the tProc counter and DMA-reads accumulated chunks of `stride = 10% of avg_maxlen / reads` shots, which is 1638 shots for us ([lib] streamer.py:96–150).
- `poll_data(totaltime=0.1, timeout=None)` returns whatever arrived within about 0.1 s ([lib] qick.py:2006–2040).

### 3.2 `acquire_decimated(soc, rounds=1, ..., progress=True, remove_offset=True, step_rounds=False)`

([lib] qick_asm.py:2169–2236)

**Return value.** Raw time traces, **averaged over rounds only, not over reps** ([lib] qick_asm.py:2238–2263):

| Case | Shape |
|---|---|
| 1 rep, 1 read | `(length, 2)` |
| multi-rep **or** multi-read | `(n_reps*n_reads, length, 2)` |
| multi-rep **and** multi-read | `(n_reps, n_reads, length, 2)` |

Here n_reps means the product of all loop counts.

**Behavior**
- It checks the request against `buf_maxlen` (16384 for us) up front ([lib] qick_asm.py:2216–2219).
- It is not streamed. Python busy-polls `get_tproc_counter` until done, then calls `get_decimated` once per channel ([lib] qick_asm.py:2320–2329).
- Use it for calibration such as time of flight and window placement, not for sweeps ([docs] topics/readout_modes.html).
- `get_time_axis(ro_index)` returns µs ([lib] qick_asm.py:1848–1869).

### 3.3 Trigger offset / time of flight

- `trigger(t=...)` is absolute in the shot timeline. **No automatic time-of-flight offset is applied** ([lib] asm_v2.py:1049–1100).
- The demos use a config `trig_time` (0.1–0.45 µs) placed after `pulse(t=0)` ([docs] tutorials/01, 06, 07).
- v1 described this as a "TOF Measurement", and stored the result as `adc_trig_offset` ([gh] qick_demos/06_qubit_demos.ipynb "TOF Measurement").
- Procedure: measure with `acquire_decimated` in loopback or through the fridge line, then set `trig_time ≈ tof` and the readout length to cover the flat part.

### 3.4 Progress, callbacks, stopping, partial results

**Progress bars.** These are `tqdm` bars ([lib] qick_asm.py:1973–1983, 2226, 2338–2357). There is no callback API. Pass `progress=False` in a server.

**`step_rounds=True`.** `acquire` returns right after preparing round 1. You then drive `finish_round()`, which returns True while rounds remain, then `prepare_round()` and `finish_acquire()` ([lib] qick_asm.py:1984–1993, 2265–2381; [docs] topics/readout_modes.html "Common setup"). Each round fills `prog.rounds_buf`, and `_summarize_accumulated` is a mean over it. **This is the natural hook for live averaged updates.**

**Partial results within a round.** You can only get these by re-implementing the accumulated branch of `finish_round`, which is about 25 lines:

```python
soc.start_readout(total, counter_addr=prog.counter_addr, ch_list=list(prog.ro_chs), reads_per_shot=[ro['trigs'] for ro in prog.ro_chs.values()])
while count < total:
    for n, (d, s) in soc.poll_data(totaltime=0.1, timeout=1.0): ...
```

Each `d[i]` is a `(n*nreads, 2)` int64 chunk of raw sums in shot order ([lib] qick_asm.py:2341–2357). With reps outermost, each chunk is one or more complete-or-partial passes over the frequency axis.

**Stopping**
- `soc.stop_tproc()` ([lib] qick.py:1868–1885) and `soc.streamer.stop_readout()` ([lib] streamer.py:59–63; `streamer` is Pyro-autoproxied, [lib] qick.py:1065).
- The next `start_readout()` cleans up any readout still running, stopping the tProc and flushing the queue ([lib] qick.py:1972–1995).
- `poll_data()` with `timeout=None` **blocks forever if no data comes**, and a stopped streamer pushes no sentinel ([lib] qick.py:2017–2030; streamer.py:121–125). Always pass a finite `timeout` in our own loop.
- After an abort, `soc.reset_gens()` silences periodic or `stdysel="last"` outputs ([lib] qick.py:1928–1950).

## 4. I and Q on two generators, 90° apart

**Pulse definition**
- Define two pulses with the same `freq` (both with `ro_ch=` the same readout, so they share the frequency grid) and `phase=0` / `phase=90`. Play both with `pulse(..., t=same)`.
- Two separate `add_pulse` calls are needed because parameters differ. Defining one pulse on a list of channels requires identical parameters and "is experimental" ([lib] asm_v2.py:2335–2387).
- The docs say: "If you have two generators that need to be phase-locked … both should be frequency-matched to the same readout … If they are matched to different readouts (or not matched), they will have slightly different frequencies and the phase between them will drift" ([docs] topics/freq_matching.html "Multiple Generators").

**Determinism of the relative phase**
- All phase-coherent DDS start times are reset together by `pl_reset` ([lib] qick.py:1314–1318).
- gen0 and gen1 sit in the same clock group as the tProc timing clock [fwREADME].
- So the **DDS** phase difference is deterministic: phase registers are exact 32-bit values ([lib] qick_asm.py:586–602).
- The analog/RFDC path difference between DAC tile 0 and tile 2 is a constant offset that must be calibrated.
- ⚠ **Not verified in sources:** whether the inter-tile datapath latency is identical after every RFDC restart. QICK 0.2.442 exposes no multi-tile-sync call: `init_tile_sync`/`sync_tiles` used in [docs] tutorials/14 do **not** exist in [lib] (grep finds nothing). Plan to re-measure the I/Q phase and amplitude imbalance after each board init.

**Mixer and IQ considerations**
- `axis_signal_gen_v6` has **no digital mixer** (`HAS_MIXER = False`, [lib] drivers/generator.py:264).
- Imbalance correction is ours to do: phase skew via `phase`, amplitude via `gain` per generator, and LO leakage. v6 has no DC-offset parameter in `add_pulse`.
- A DC offset could be emulated with an `outsel="input"` envelope, since an `arb` pulse with `outsel="input"` outputs the table's real part ([lib] asm_v2.py:1609–1618). This is untested.

## 5. Nyquist zones, `nqz`, mixer and frequency limits, power

**`nqz`**
- `declare_gen(nqz=1|2)` calls `soc.set_nyquist` per DAC in `config_gens` ([lib] qick_asm.py:1365–1380).
- "This setting doesn't change the DAC output frequencies: you will always have some power at both the demanded frequency and its image(s). Setting the NQZ to 2 increases output power in the 2nd/3rd Nyquist zones" ([lib] qick.py:638–664).
- Helpers: `qick.helpers.nqz(f, fs)`, `folded_freq`, `nyquist_image` ([lib] helpers.py:260–280).

**`mixer_freq`.** Not applicable to our generators. `declare_gen(mixer_freq=...)` on a no-mixer generator just warns ([lib] qick_asm.py:1340–1342). No mixer also means no 0.7 "fullscale" factor; that factor applies only to RFDC fine mixers ([lib] qick_asm.py:1316–1318).

**Generator range**
- DDS range = fs/interpolation = 9830.4 MHz [fwREADME]. `freq2reg` enforces ±range/2 **only when interpolation ≠ 1**. For us it simply wraps modulo 2^32 ([lib] qick_asm.py:436–466).
- First Nyquist zone ≤ 4915.2 MHz. Above that you are in the 2nd zone (use `nqz=2`).
- The QICK overview claims "direct synthesis of pulses up to 6 GHz" ([gh] qick_demos/README.md). Real usable power vs frequency depends on the DAC sinc roll-off and the 4x2 front end, which are not in these sources. Measure them.

**Readout range**
- DDS range 4423.68 MHz, first Nyquist zone ≤ 2211.84 MHz [fwREADME].
- The register wraps modulo 2^32 ([lib] qick_asm.py:468–491).
- Decimated output rate 552.96 MHz = fs/(1·8) ([lib] drivers/readout.py:31, 457).

**Power and gain mapping**
- QICK gives no dBm calibration. `gain` is a fraction of DAC full scale (32766) ([lib] §1.3).
- Coarse knobs:
  - DAC output current: `set_dac_curr`, VOP mode, Gen3 only and only if enabled in firmware ([lib] qick.py:763–790). Our firmware reports a fixed "20mA" mode [fwREADME].
  - ADC step attenuator: `soc.set_adc_attenuator(blockname, dB)`, 0–27 dB in 1 dB steps, Gen3/4x2 ([lib] qick.py:712–730, 1633).
- **dBm requires our own calibration table** vs frequency.

## 6. Pyro4 client

### 6.1 `make_proxy` and IPython

`qick.pyro.make_proxy(ns_host, ns_port=8888, proxy_name='myqick', remote_traceback=True)` does the following ([lib] pyro.py:99–147):
1. Sets `Pyro4.config.SERIALIZER = "pickle"` and `PICKLE_PROTOCOL_VERSION = 4`.
2. Calls `locateNS` and **prints** `ns.list()`.
3. Creates `soc = Pyro4.Proxy(ns.lookup(name))` and `soccfg = QickConfig(soc.get_cfg())`.

**What IPython is for.** If `remote_traceback=True`, it imports IPython and installs a custom exception handler that prints `Pyro4.util.getPyroTraceback()`. **Any** failure there, including `import IPython` failing, is re-raised as `RuntimeError("Failed to set up Pyro exception handler")`. IPython is **not installed** in our `.venv`, so the default call raises. Use `make_proxy(..., remote_traceback=False)`, or replicate it:

```python
import Pyro4
from qick import QickConfig
Pyro4.config.SERIALIZER = "pickle"; Pyro4.config.PICKLE_PROTOCOL_VERSION = 4
ns = Pyro4.locateNS(host="192.168.3.1", port=8888)
soc = Pyro4.Proxy(ns.lookup("rfsoc"))
soccfg = QickConfig(soc.get_cfg())
# remote traceback for logs:  except Exception: log("".join(Pyro4.util.getPyroTraceback()))
```

This mirrors [gh] pyro4/02_client.ipynb cells 1–5. The proxy name `"rfsoc"` and port 8888 come from our `board/qick_service.py`.

### 6.2 What runs where, and what crosses the wire

- **Programs are compiled client-side** from `soccfg`, which is a plain config dict ([lib] asm_v2.py:2726–2762; [gh] pyro4/02_client.ipynb: "you need to create a QickConfig object that contains all the information necessary to compile programs").
- **`acquire*` runs client-side.** Only `soc.*` calls cross the wire:
  - `start_src`, `stop_tproc`, `load_envelope`, `set_nyquist`, `load_bin_program`, `config_avg`/`config_buf`/`enable_buf`, `reload_mem`, `clear_tproc_counter`, `start_readout`/`poll_data` or `get_tproc_counter`/`get_decimated`/`get_accumulated` ([lib] qick_asm.py:1094–1128, 1273–1295, 2265–2366).
  - Envelopes and weights are sent as Python lists "for pyro compatibility" ([lib] qick_asm.py:1616–1634).
  - The binary program is a dict of lists ([lib] asm_v2.py:2167–2175). The board converts it back to numpy ([lib] qick.py:1768–1786).
- **Server.** `start_server` sets `REQUIRE_EXPOSE=False` (all `QickSoc` methods are remote) and pickle-only. It registers `soc.streamer` and `soc.tproc` for autoproxying ([lib] pyro.py:54–94; qick.py:1036, 1065). It advertises the interface facing the nameserver, falling back to `iface='eth0'` only if that resolves to loopback ([lib] pyro.py:63–77). Our nameserver binds 192.168.3.1, so the USB-link address is used.
- **Version check.** `QickConfig(cfg)` logs "QICK library version mismatch … usually KeyError in QickConfig initialization" when the board's `sw_version` differs from the local one ([lib] qick_asm.py:36–51). Board and PC are both 0.2.442.
- **Security.** Pickle is the serializer, so anyone who can reach the daemon can execute code. This is acceptable only on the point-to-point USB link.

### 6.3 Performance

- **Round trips.** Each `soc.x()` is one round trip.
  - Per `acquire()` call (one round) there are roughly 15–20 setup RPCs plus one `poll_data` RPC per ~0.1 s (counted from the code paths above).
  - Per `acquire_decimated` round there are many `get_tproc_counter` RPCs, since it busy-polls with no sleep ([lib] qick_asm.py:2320–2324).
- **Payload.** Accumulated data per shot per read is 2×int64 = 16 bytes (dtype from [lib] qick_asm.py:1967), so 100 k shots ≈ 1.6 MB.
- **No measured Pyro latency or throughput in the official sources.** Benchmark it ourselves.

### 6.4 Thread-safety and concurrent access

- **Board side.** Pyro4 4.82 defaults to `SERVERTYPE="thread"` with `THREADPOOL_SIZE=40` (local `.venv/.../Pyro4/configuration.py:49,56`; the board's Pyro4 version was not checked). Calls from different clients or proxies execute **concurrently**.
- **`QickSoc` has no locking.** "We don't lock the QickSoc or the IPs. The user is responsible for not disrupting a readout in progress" ([lib] streamer.py:24).
- **Client side.** A single `Pyro4.Proxy` serializes its calls with an internal `RLock` ([Pyro4 4.82] core.py:244, 426). Sharing one proxy across threads is safe but sequential, so a long `poll_data` blocks other calls on that proxy.
- **Conclusion.** Exactly one experiment runner may touch the board at a time, which ADR-0003 already assumes. Run abort and status calls in the same worker loop, or on a separate proxy with care.

## 7. Two-tone spectroscopy and Rabi in the official demos

- **No tProc v2 qubit demos exist** in 0.2.442. The v2 tutorial list (00–15) covers sequencing, sweeps, timing, feedback, generators/readouts, buffers and synchronization ([docs] tutorials/README.html).
- The qubit experiments are only in the **tProc v1** notebook [gh] qick_demos/06_qubit_demos.ipynb, which the docs call "Qubit demos: working with a real qubit" ([docs] tutorials/README.html).

**Structure of the v1 demos ([gh] qick_demos/06_qubit_demos.ipynb)**

1. **Resonator spectroscopy** (`SingleToneSpectroscopyProgram(AveragerProgram)`): a Python loop over `fpts`, building a program per point and calling `acquire(soc)`, then `amp = |I+jQ|`.
2. **Pulse-probe (two-tone)** (`PulseProbeSpectroscopyProgram(RAveragerProgram)`):
   - The resonator is fixed at `f_res`.
   - The qubit generator (`nqz=2`) frequency is swept in the tProc with `start`/`step`/`expts`.
   - Body: `pulse(qubit)`, then `sync_all(0.05 us)`, then `measure(res_ch, adcs, adc_trig_offset, wait=True, syncdelay=relax_delay)`.
   - It is acquired with `threshold=` for qubit population.
3. **Length Rabi**: a Python loop over the qubit `pulse_length` (`AveragerProgram`).
4. **Amplitude Rabi** (`AmplitudeRabiProgram(RAveragerProgram)`): Gaussian `add_gauss(sigma, 4σ)`, `style="arb"`, with gain swept in the tProc. It is followed by T1, Ramsey and active reset in the same style.

**v2 equivalents built from the v2 API.** These are not an official demo, only a direct translation using [docs] topics/tprocv2_migration.html and tutorials/02:

```python
class TwoTone(AveragerProgramV2):
    def _initialize(self, cfg):
        self.declare_gen(ch=cfg['res_ch'], nqz=1); self.declare_gen(ch=cfg['qb_ch'], nqz=cfg['qb_nqz'])
        self.declare_readout(ch=cfg['ro_ch'], length=cfg['ro_len'])
        self.add_loop("f", cfg['steps'])
        self.add_readoutconfig(ch=cfg['ro_ch'], name="ro", freq=cfg['f_res'], gen_ch=cfg['res_ch'])
        self.send_readoutconfig(ch=cfg['ro_ch'], name="ro", t=0)
        self.add_pulse(ch=cfg['qb_ch'], name="probe", style="const", length=cfg['probe_len'],
                       freq=QickSweep1D("f", cfg['f_start'], cfg['f_stop']), phase=0, gain=cfg['qb_gain'])
        self.add_pulse(ch=cfg['res_ch'], name="meas", style="const", ro_ch=cfg['ro_ch'],
                       freq=cfg['f_res'], length=cfg['res_len'], phase=0, gain=cfg['res_gain'])
    def _body(self, cfg):
        self.pulse(ch=cfg['qb_ch'], name="probe", t=0)
        self.delay_auto(0.05)                       # v1 sync_all(0.05us)
        self.pulse(ch=cfg['res_ch'], name="meas", t=0)
        self.trigger(ros=[cfg['ro_ch']], t=cfg['trig_time'])
# Amplitude Rabi: add_gauss(...) + style="arb", gain=QickSweep1D("g", 0, 1)
# Length Rabi:    style="const", length=QickSweep1D("l", l0, l1); delay_auto() keeps the readout after it
```

Use `prog.get_pulse_param("probe", "freq", as_array=True)` for the x axis.

**Fluxonium caveat.** Fluxonium qubit drive at MHz frequencies goes directly from a DAC, with `freq` in MHz and `nqz=1`. Whether the 4x2 DAC baluns pass low MHz is a hardware question, not covered in these sources.

## 8. Gotchas

1. **Wrong bitfile.** The pip package ships a different `qick_4x2.bit` (no dynamic readouts). Always pass the board's firmware path. See the top of this file.
2. **`declare_readout(freq=...)` raises on dynamic readouts.** Some doc examples do this ([lib] qick_asm.py:1218–1219).
3. **Frequency matching needs both `ro_ch` and `gen_ch`.** Otherwise the phase is run-to-run random ([docs] topics/freq_matching.html).
4. **`make_proxy()` raises without IPython** unless `remote_traceback=False` ([lib] pyro.py:134–145).
5. **Tutorial code can be wrong for 0.2.442:**
   - `delay_auto(gap=0.1)` ([docs] tutorials/09 §3.1); the real signature is `delay_auto(t=0, gens, ros, tag)` ([lib] asm_v2.py:1420).
   - `soc.init_tile_sync()` ([docs] tutorials/14) does not exist in [lib].
   - Tutorial 02 says the decimated data shape is `(reps, loop1, loop2, …)`, but `acquire()` averages reps away ([lib] qick_asm.py:2041–2062).
   - **Trust the source.**
6. **Program size.** pmem 4096 / dmem 16384 / wmem 1024 words [fwREADME]. Exceeding them raises at compile time ([lib] asm_v2.py:2176–2180). Every distinct pulse or readoutconfig uses wmem, so don't define one pulse per frequency; sweep instead.
7. **Pulse length limits.** 3 ≤ length < 2^16 fabric cycles per waveform, so ≤ about 106 µs at 614.4 MHz ([lib] asm_v2.py:1729–1734). For long CW use `mode="periodic"` and stop it with `"dummypulse"`.
8. **Readout window.** Keep it ≤ 2^16 decimated samples (about 118 µs) to avoid sum overflow ([lib] qick_asm.py:1199). The decimated buffer is 16384 samples (29.6 µs total per acquisition) [fwREADME].
9. **ro2's weighted buffer.** With `weights=None`, the library loads `min(length, wgt_maxlen=4096)` weights of `[2**15-2, 0]` ([lib] qick_asm.py:1626–1634). Behavior for windows longer than 4096 samples (7.4 µs) on ro2 is **unverified**. Prefer ro0/ro1 for long windows, or test ro2.
10. **Sweep end points are truncated toward zero.** Always use `get_pulse_param(..., as_array=True)` for the frequency axis ([lib] asm_v2.py:295–310; [docs] tutorials/09 §3.3).
11. **Streamer overflow.** If shots are faster than the board can DMA, you get "Overflowed the averages buffer … increase relax_delay" ([lib] streamer.py:136–141). Our equivalent knob is `final_delay`.
12. **`clear_tproc_counter` resets the tProc** on v2 (it zeroes all registers) ([lib] qick.py:1887–1903).
13. **Leftover outputs.** `stdysel="last"` and periodic pulses keep playing after a program ends. Call `soc.reset_gens()` ([lib] qick.py:1928–1950).
14. **Board re-init changes φ0.** `pl_reset` or tile restarts reset or randomize DDS phase references ([lib] qick.py:346–351, 1314–1318). Phase calibrations (electrical delay, φ0, IQ skew) belong to a board session.

## Implications for our app

1. **Connection.** Build the proxy without IPython: the 5-line snippet in §6.1, or `make_proxy(..., remote_traceback=False)`. Log `Pyro4.util.getPyroTraceback()` on errors. At startup, check that `soccfg['sw_version'] == qick.__version__` and that the tProc revision is supported. Treat a mismatch as a hard error.
2. **One owner of the board.** A single worker thread in FastAPI owns the `Pyro4.Proxy` and runs one measurement at a time. Every other request (status, abort) goes through a queue or flag that the worker checks between `poll_data` calls. `QickSoc` has no locks and the Pyro server is multithreaded (§6.4).
3. **S21 = one in-tProc program per sweep** (§2.1):
   - `QickSweep1D` on both the generator pulse `freq` (with `ro_ch=`) and the readout config `freq` (with `gen_ch=`).
   - `send_readoutconfig` goes in the loop's `exec_before`, reps outermost, `acquire()` (accumulated), `progress=False`.
   - The frequency axis comes from `get_pulse_param("ro", "freq", as_array=True)`.
   - Constrain the requested step to ≥ the common step (`soccfg.calc_fstep([gencfg, rocfg])`, about 20.6 Hz) and show the user the rounded grid.
4. **Live plots** (§3.4):
   - Use `rounds=N, step_rounds=True` and push the running mean of `prog.rounds_buf` to the browser after each `finish_round()`. This is the simplest option.
   - For sub-round updates, re-implement the accumulated branch of `finish_round` with `soc.poll_data(totaltime=0.1, timeout=1.0)` and accumulate chunks into `acc_buf`.
   - Abort means `soc.stop_tproc()` + `soc.streamer.stop_readout()` + `soc.reset_gens()`. Never call `poll_data` with `timeout=None`.
5. **Units on display.** Show `|S21|` as 20·log10 of the mean I/Q amplitude in ADC units (length-normalized, §3.1), relative to a stored reference trace, until we have a dBm calibration. Phase is shown after subtracting a fitted electrical delay (`np.unwrap` + linear fit, §2.3), with an optional manual delay entry like a PNA "electrical delay" setting.
6. **Calibration routines are first-class features:**
   - (a) time of flight via `acquire_decimated` (single rep), which sets `trig_time` and the readout window;
   - (b) electrical delay and φ0 from a wide loopback sweep;
   - (c) for the transmon IQ setup, the gen0/gen1 phase skew and gain imbalance.

   Store them per board session and invalidate on board re-init (gotcha 14).
7. **Transmon I/Q output.** Two `add_pulse` definitions with the same frequency grid (both `ro_ch=` the same readout) and `phase=0` / `phase=90+skew`, per-generator `gain`, played at the same `t`. For two-ADC IQ return, `trigger(ros=[0, 1])` with identical readout configs (frequency matched to the same generator), then combine `I_ro0 + j·I_ro1` after per-channel offset/skew calibration. That combination is our software, not QICK.
8. **Fluxonium setup.** Generator frequency is the IF on the external LO. Use `nqz=1` unless the IF is above 4915 MHz. Readout frequency must be the same IF, ≤ 2211 MHz for first-Nyquist ADC operation.
9. **Guard rails in the request validator:**
   - pulse ≤ about 106 µs (or periodic);
   - window ≤ about 118 µs;
   - decimated total ≤ 16384 samples;
   - step count × `final_delay` consistent with streamer throughput (start with `final_delay ≥ 1 µs`);
   - no per-point pulse definitions (waveform memory is 1024 entries).
10. **Measure Pyro latency and throughput ourselves** (none is published). Benchmark a 1001-point × 100-rep S21 over the USB link and compare it to the 0.37 s on-board figure (§2.1).
